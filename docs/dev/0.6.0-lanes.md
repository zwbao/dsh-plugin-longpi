# LongPi 0.6.0 lanes

`0.6.0` is the release. Lanes built on the `0.6.0-dev.0` contract revision (C1). Installing `dsh-plugin-longpi` installs dsh and the complete longevity-skills library. dsh's agent drives the library. The plugin supplies data, validates bindings (units, ranges, provenance), labels a result `verified`, `unverified-binding`, or `evidence-only`, and enforces the safety hard rules. It does not select, rank away, hide, or gate a method.

Shared types and the function signatures live in `src/contracts/library.ts`. `FactPack.method_results` is the list of `MethodResult` for this generation. Until a lane registers, `listSkillIndex`, `validateBinding`, `readStore`, and `methodResults` throw `not implemented in C1`. `registeredMethodResults()` is `[]`, and that is what the fact pack stores.

## How a lane plugs in

`src/index.ts` `apply()` calls `mountLibraryLanes(ctx)` after the harness skills. It does not import lane files. A lane registers from a module this process already loads, so it does not edit `src/index.ts` or `src/contracts/library.ts`.

```ts
import { registerLibraryHooks, registerLibraryMount } from './contracts/library.ts'

registerLibraryHooks({
  listSkillIndex: () => [],
})

registerLibraryMount((ctx) => {
  // ctx is the cordis context apply() received. Narrow it in the lane.
})
```

`registerLibraryHooks` replaces only the keys that call passes. `registerLibraryMount` appends. Both return an unregister function.

| Lane | Register from (already imported) |
| --- | --- |
| L1 | No runtime hook. Packaging and `versionCheck` only. |
| L2 | `src/tools.ts` or `src/match.ts` |
| L3 | `src/datain/register.ts` |
| L4 | `src/core/topfacts.ts` (imported by `src/core/factpack.ts`) |

## File ownership

Do not edit another lane's files. Do not edit the shared rows.

| | Owns | Does not edit |
| --- | --- | --- |
| **Shared (C1)** | `src/contracts/library.ts`, `src/contracts/factpack.ts` (`method_results` field), `src/index.ts` (exports and `mountLibraryLanes`), `src/version.ts` `PRODUCT_VERSION`, this file | Lane implementations |
| **L1** packaging, install, update, version pin | `package.json` (`bin`, `dependencies`, `files`; leave `version` at `0.6.0-dev.0`; no `postinstall`), `bin/`, `install.sh`, `versionCheck` in `src/tools.ts` | Skill index, binding, stores, fact pack |
| **L2** skill provider, binding, run path | `src/skills-provider.ts`, `src/bind.ts`, `src/match.ts`, the run path in `src/runner.ts` and `src/tools.ts` (`run_longevity_skill`), `skills/longpi-dispatch/` | `versionCheck`, store files, page rendering |
| **L3** typed stores | `src/stores/*`, the upload type field in `src/datain/upload.ts` and `src/datain/routes.ts`, proposals in `src/agents/report_reader.ts`. Register `readStore`. | `src/bind.ts` (L2 calls `readStore`) |
| **L4** fact pack and page | `method_results` population via the `methodResults` hook (the fact pack already calls `registeredMethodResults()`), ranking in `src/core/topfacts.ts`, `src/client/results.ts`, `src/surfaces/fallback.ts` | The `MethodResult` type |

L1 and L2 both touch `src/tools.ts`. L1 owns `versionCheck`. L2 owns the run-tool path. Keep those edits apart.

## What the plugin still does not do

- `listSkillIndex` returns every catalog entry. Tier C is evidence, not a hidden tier.
- `validateBinding` checks the manifest key, the unit, the range, and provenance. It does not choose the skill.
- A methylation `PhenoAge` is `methylation_clock`. It does not satisfy `blood_clock`. Coronary calcium is `coronary_ct`. It does not satisfy `abdominal_ct`.
- `verified` is a LOINC, a device code, a profile field, or an `output_of` link that passed the checks. `unverified-binding` passed the checks on a row the model named. `evidence-only` has no personal number.
- Safety stays in code: skill scripts produce numbers, reference-change bands, emergency and plan-safety stops, approvals, and the four-tier advice policy.
